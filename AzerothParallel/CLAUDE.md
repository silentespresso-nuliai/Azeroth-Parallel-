# 项目开发与约束规范 (CLAUDE.md)

## 一、 核心铁律（绝对禁止违反）
- **严禁引入外部依赖**：不新增第三方库或外部下载；插件只使用 `AzerothParallel` 文件夹内的 `.toc`、`.lua` 与本地 `Media` 资源（TGA / OGG）。
- **严禁盲目读取文件**：在读取文件前必须确认目标。除非我明确要求，否则严禁一次性扫描或阅读整个目录。只阅读与当前任务直接相关的 1-2 个文件。
- **禁止长篇大论**：严禁任何客套话（如“好的”、“没问题”）。严禁解释显而易见的代码。
- **强制局部输出**：修改代码时，只输出被修改的那一段代码（或 Diff 差异），严禁重新输出整个完整文件。
- **系统安全限制**：只允许读取、修改或删除当前插件目录（`AzerothParallel`）内的文件；严禁访问父目录 `my-first-claude` 或系统其他位置。确有需要时先停下来用中文说明原因并申请授权。

## 二、 插件资产隔离
- **主面板视觉**：书本底图 `Media/Book.tga`、页签与职业书签 `Media/Ribbon.tga` 由 `Core.lua` 统一加载；书页文字颜色一律走 `AP_Theme`，不要在单个模块里另造一套书页配色。
- **深色面板**：表情动作卡片、3D 正面形象、高光特写覆盖层是独立深色视觉，**严禁**把书页的浅色/墨水配色混进去，反之亦然。
- **音效**：`Media/sounds/` 是留给用户自己放自定义音效的目录；代码引用缺失文件时静默兜底，不因缺少音效报错，也不要强制补文件。
- **模块职责**：`Core` 主框架与主题、`Danmaku` 弹幕与设定页分页、`Flavor` 职业流派与称谓典籍、`Emotes` 表情卡片与正面形象、`Spotlight` 高光特写、`Terms` / `Data` 纯数据、`Network` / `Peers` 同好名录、`Overrides` 鼠标提示、`Nameplate` 姓名版（新客户端停用）。改动前先确认落在哪个文件。

## 三、 代码与注释规范
- **变量优先**：颜色与字号必须优先修改 `Core.lua` 的 `AP_Theme`（`ink` / `inkSoft` / `accent` / `cream` / `line`），严禁在各模块里重复硬编码同一套主题色。
- **注释风格**：追加新代码时，必须延续插件现有“小白友好型”的详细中文注释风格。

## 四、 工作流
- 插件无法自动启动魔兽世界；修改完成后提醒我在游戏内 `/reload`，再用 `/AP` 和对应页面核验。
- 每次完成阶段性任务，主动提醒我执行 `git commit` 进行存档。

## 五、 语言与交互规范
1. **强制中文**：无论你在思考过程（Thought）、执行计划、报错分析、还是最终输出中，**必须全部使用简体中文**。
2. **禁止英文长句**：如果你需要解释代码或报错，请用通俗易懂的中文向我说明，严禁直接甩出一段无翻译的英文。
3. **请示与确认**：当你需要我提供信息、或者请求权限时，必须用中文明确提问（例如：“我需要修改某文件，是否允许？”）。

## 冲突处理机制（最高优先级）
1. 当你准备执行的任务，与我本次 Prompt 的最新指令，与本 `CLAUDE.md` 中定义的“核心铁律/技术栈/目录结构”产生直接且严重的矛盾时：
2. **绝对禁止擅自修改规则，也绝对禁止默默按最新指令执行。**
3. 你必须立即停下，用中文向我提示：“⚠️ 警告：当前指令与 CLAUDE.md 的【某某规则】冲突。”
4. 必须等我明确回复“**强制覆盖**”这四个字后，你才可以按照本次的 Prompt 执行。如果我没有回复这四个字，请维持原规则。
